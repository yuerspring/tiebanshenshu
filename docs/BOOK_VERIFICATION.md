# 用户提供 PDF 的算法核验记录

本轮核验针对用户提供的本地 PDF，页码均为 **PDF 从 1 开始的页序**，不使用浏览器工具条固定显示的“144/205”。没有将整份 PDF 上传到仓库。

## 文件身份与核验范围

文件名题为《铁板神数 邵雍著 陈明点校》，但实际有 144 页，页眉为《陈抟—铁板神数秘旨—道客巴巴》，第一页是网页资料信息；包含现代排版说明及多个门派章节。现有内页不能证明该文件是陈明点校本或邵雍原著。正文中关于作者、门派和效验的说法只是该文档的自述，未作历史定论。

本轮已目视核读第一章关键推演步骤、部分实例及表格，属于**选定规则与算例的核验**，不是 144 页全部内容、12,000 条正文或所有扩展模块的校勘。程序能重现算例不等于证明预测准确。

文件 SHA-256：`5ab705b5f869fb624bb2979e60bac5f028071fdeeaca54221068f771f695a458`。

### 为什么分钟相同

第一章本命公式的输入是农历月份、出生时支、年干、日柱纳音、求测时柱纳音与天干、性别、农历生日，没有出生分钟变量。第14页还明确区分本章的两类刻别与未在本章给出完整规则的高级八刻；提到“十五分”不等于提供了逐分钟取数公式。

当前 `keke_module` 的六亲八刻候选是另一路旧规则，尚未由本次书页确认，不能把候选刻强行注入第一章本命公式。API 的 `method_basis` 和页面计算依据已说明这一点。候选没有共同交集时保持未确定。

### 默认值处理

十四表核心取数不再在缺表、缺键或纳音未知时默填“宫”“金”或0。这些默认值会把不完整数据库变成看似完整的命数。缺失必需数据现在中止计算；既有卦名缺项则继续明确报告并停止生成该本命条文。

## 回归方法与边界

`tests/test_book_examples.py` 直接使用文档给出的农历日、四柱与求测时柱作算例，不凭空补出书中未写明的公历求测日期。用于构建载荷的公历日期只是容器，已显式覆盖算例规定的字段；本测试不验证历法换算。

本轮覆盖：实例二完整本命路径、前16岁原始流年条号、369两种刻别、表14-1至14-6的核读矩阵、缺表不默认、API精度说明。原始CSV哈希基线保留原始来源提交，另附本次单格修订记录。

仍未完成：后续章节的完整独立算法、八刻/十五分的原文全流程、12,000条逐字比对、表14-11全部序列的逐行核验、真太阳时和地域规则。不能把这些部分标为“古籍已验证”或“官方精确到分钟”。
