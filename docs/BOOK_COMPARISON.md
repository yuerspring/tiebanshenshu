# 徐宇辳本、金泉本与现有算法的定点核验

本轮根据维护者提供的两份扫描 PDF 核对考刻章节、配数规则和部分条文案例。不是两本共 815 个 PDF 页面的逐字校勘，也不是对预测准确率的验证。页码下文同时区分 PDF 文件页和书内印刷页。不将扫描书籍或整部转录上传仓库。

## 来源与查阅范围

- 《铁板神数大公开》，徐宇辳，270 个 PDF 页。核看封面、序、目录、PDF 31–42 页考刻相关内容及 PDF 180 页条文样本。双页扫描；PDF 39 页对应印刷 68–69 页，PDF 40 页对应 70–71 页。
- 《铁板神数预测学》，用户文件名署金泉编，545 个 PDF 页。核看目录、PDF 43–50 页六亲条文表、66–82 页考刻、定刻及元堂规则。PDF 68、69、72 页对应印刷 65、66、69 页。此处不依据文件名认定为邵雍亲著或官方标准。

## 一、查出并修复的实际流程错误

金泉本 PDF 68 页规定：先用基本卦和互卦取数查条文，符合已知事实才作为基本数；不符时逐爻变化。PDF 69 页说明先选定符合事实的卦，再进行 ±48×2、4、8、16。后天运程也列出同样的查验步骤。

原来的 `calculate_kaoke_qushu` 与 `calculate_houtian_yuncheng` 有两处错误：

1. 只将六个变卦传入核验回调，基本卦没有查条文、没有接受核验。
2. 没有核验条件或没有候选匹配时，仍选择基本卦，继续生成加减推演。

现将基本卦和六个变卦统一核验一次；新增独立的 `kaoke/verification.py`，两个方法共用。结果区分 `not_provided`、`no_match`、`ambiguous` 和 `unique_candidate`。只有唯一匹配才给出 `best_number` 与后续加减数，其他情况保留全部候选，最佳候选为 null。多匹配保留歧义是软件防止任意选择的处理，不声称书中规定了这种状态名。回调只能代表调用者给定条件，不是命理真实性证明。

## 三、为什么不能人为做到“每一分钟必然不同”

徐本 PDF 31 / 印刷52专门区别刻分与钟表刻度；PDF 36 / 印刷62另述一日百刻的分配。PDF 40 又示范以已知父母生肖检验、必要时调整五分或取对宫。这种方法需要明确本派规则和事实核验，不能简化为出生分钟直接加一个数。

金泉本 PDF 72 / 印刷69则另列“定刻取数法”，说明一刻15分钟、查八刻数表，再作两位数字相加、后天卦、纳甲、加则及 ±96 推演。它是另一条完整流程，不能只拿“15分钟”拼进原主公式。

因此相邻分钟结果相同，本身不能证明程序有误；程序缺失分钟变量、错误默认、以及漏掉事实核验是三个不同问题。已经修复的是核验流程错误。尚未把未核全的八刻表或徐本流度口诀混入现有十四表主算法。

## 四、下一步有依据的改良边界

- 将徐本流度、金泉六亲考刻、金泉定刻分别建立方法版本，分别保存出处、完整表格、输入和中间步骤；不要共用含义不同的配数表。
- 先固定条文底本，再处理2207等跨版本差异；9053须找到完整原句后才能更正。
- 后天减10所得零/负值、五数寄宫等边界仍需逐条查明出处，不能用默认坤卦或默认数字替代校勘。
- 金泉八刻数表尚未完成逐格核验，元堂章节本轮仅识别规则，未宣称实现或验证。
- 公开案例只验证可复算的取数与条文对应，不把叙述吻合统计成预测准确率。

## 验证

新增6项测试覆盖基本卦核验、无条件、无匹配、多匹配、变卦唯一匹配、太玄表与派生手算，以及徐本四个父母案例（部分场景在同一测试内循环）。完整测试48项通过。数据审计仍报告原先十四表正刻670重复、700缺失，未擅自修补。
