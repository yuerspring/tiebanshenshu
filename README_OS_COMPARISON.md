# TiebanshenshuOS 原版对照

网站 `/api/v1/compare-os` 对同一输入分别调用当前 V2 与 `Nanphy/TiebanshenshuOS` 原始计算器。`reference_os/main.py` 来自公开仓库提交 `785dc871d523e1c4d7772946955fd30fc8ebb4bf`，只在适配层显式设置绝对数据库路径并关闭其向本机调试服务器发送数据的钩子。未更改原代码中的公式。前台显示两个独立结果；V2 仍为主排盘。

## CSV 差异

去除 UTF-8 BOM 和末尾换行后，两版 `14-10.csv` 与 `List.csv` 以及多数表完全相同。只有以下表有内容差异：

| 文件 | 原版 OS | V2 |
| --- | --- | --- |
| 14-11-1.csv，亥卯未、男的起始数 | 12 | 2 |
| 14-11-2.csv | 两行十二音序列不同 | 两行十二音序列不同 |
| 14-13.csv，初刻／奇数／四／石 | 福 | 神 |

Docker 仅携带以上三个 OS 专属 CSV，其余相同数据复用现有 V2 文件；对照计算没有采用 V2 专属秘数、人名数据。为避免意外忽略原版数据库变化，更新参考版时需重新对比 CSV。

## 已核对的代码行为

- OS 的 `get_eight_ke_from_time` 把普通奇数小时加上 60 分钟；05:30 返回「六刻」（刻干数 7），而 V2 返回初定第 3 刻。该两版差异不能当作出生分钟校准依据。
- OS 的“六亲考刻分析”调用在 `calculate` 里被注释，测试脚本只检查计算没有抛异常。兄弟生肖或人数没有改变本命查表。
- OS 有独立的 `本命基数 + 刻干数 × 48` 终局条文号及流年计算规则，但这些没有经过已知事实的独立准确性验证。
- 已知示例的兄弟条文在两版都写作「兄弟三人」；不能把两版一致误当成事实正确。

`python -m unittest discover -s tests -v` 测试参考版 API 返回内容与归档原计算器完全一致，并保留 V2 的回归测试。
